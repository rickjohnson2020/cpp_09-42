- Ford–Johnsonアルゴリズムとは？
データの比較回数を数学的な極限まで減らすために作られた特殊なソートアルゴリズム
1. 要素をペアにして大小を比べ、大きい方の要素を再帰的に並び替る
2. 残った小さい要素を配列に挿入する際、ヤコブスタール数という数列を使って挿入の順番を最適化し、比較回数を最小限にする


- Jacobsthal数とは？
J(0)=0, J(1)=1, J(n) = J(n−1) + 2·J(n−2)
J: 0, 1, 1, 3, 5, 11, 21, 43, 85, ...


- マージインサーションソートでの最悪比較回数の理論値とはなに？

長さ n の列に二分挿入するとき、必要な比較回数は最悪で ⌈log₂(n+1)⌉ 回

- なぜJacobsthal順だと最悪比較回数が減るのか
Ford-Johnsonでは、どの b を先に挿入するかによってBinary Searchする範囲の大きさをコントロールできる。
Binary Searchでは要素数が 1, 3, 7, 15, 31...(2^k - 1)の探索範囲だと効率がいい。(比較回数がk回で済む)。
↓
じゃあ探索範囲がなるべくそのサイズになるようにbの挿入順序を変えよう
b3  → 探索範囲3
b5  → 探索範囲7
b11 → 探索範囲15
b21 → 探索範囲31

そこから逆向きに入れる。
b3 → b2
b5 → b4
b11 → b10 → b9 → b8 → b7 → b6
b21 → b20 → ... → b12

そうすると
partnerが1つ前へ
        ↓
探索範囲 -1
直前のbを追加
        ↓
探索範囲 +1
        ↓
探索範囲が上限を超えない！

- `std::vector<int>::const_iterator it`のようなイテレータとは？
ポインタと似ていて、itはベクターの中のどれかを指している。
`it = v.begin();`の場合ベクターの最初の要素のイテレータ。
*itでその値が取れる。
厳密にはiteratorは「アドレス」ではなく、「要素を指し示すためのオブジェクト」。



- なぜvectorとdequeを選んだのか？vector, dequeとは何？
どちらもランダムアクセスができ、Ford-Johnson Sortの実装に向いているから。
このアルゴリズムでは、要素へのアクセス、lower_bound() による二分探索、途中への insert() などを頻繁に使う。
vector と deque はどちらもランダムアクセスイテレータを持つため、ほぼ同じアルゴリズムを実装して性能を比較しやすい。

vector：要素が連続したメモリに保存される。ランダムアクセスが速く、キャッシュ効率も良い。
deque：要素が複数のメモリブロックに分かれて保存される。ランダムアクセスは可能だが、メモリ構造がvectorとは異なる。

deque: double-ended queue


- 結果の考察
vectorは連続したメモリにデータを持つのでキャッシュ効率が良く、今回のようにfindやlower_boundで何度も要素へアクセスする処理では有利になった可能性があります。
dequeもランダムアクセスはO(1)ですが、複数のメモリブロックに分かれているので、今回の実装ではvectorより遅くなったと考えれる。
